## 四、新增项目经历（核心 — 建议整段进简历）

建议标题与美匠并列，时间可用 `2026.8` 或 `2026.7-2026.8`（按你实际）：

```text
签证客服智能体（个人项目｜独立负责）                                    2026.8
项目描述：面向因私签证/文旅客服场景的 AI Agent Demo。将售前咨询拆为可执行工作流：
意图分流、材料槽位追问、知识库问答、订单进度工具调用、投诉与高风险转人工、中风险用户确认；
对用户输出可追溯、可评测的客服话术，红线场景禁止出签承诺与编造政策。

技术栈：Python / LangGraph；Coze Coding（LLMClient + 知识库）；Mock 订单进度插件；
静态 H5 对接 /run；知识库文档（各国 FAQ / 材料清单 / 风险政策）。

个人职责：
1. Agent 工作流编排：基于 LangGraph StateGraph 设计 5 类意图（faq/material/progress/complaint/
   chitchat）条件路由；实现「材料先槽位后检索、进度先校验后调工具、投诉规则转人工」等分支，
   避免单超级 Prompt 不可测、不可控。
2. 知识库与防幻觉：配置签证知识库语义检索；回复侧强制只依据检索/插件结果；空结果明确「暂未查到」
   并引导官网或人工，禁止模型通识伪装成查库结论（与美匠 rag-min-score 诚实策略一脉相承）。
3. 工具调用与异常路径：订单号整句提取与格式校验；Mock 查进度；查无/插件失败友好兜底，绝不编造进度；
   说明正式环境可替换为真实工单/电商客服 API，节点边界保持稳定（开闭原则）。
4. 权限门控（对标 Agent Trainer JD）：风险关键词评估 low/medium/high；统一输出 flow_path=
   ask/confirm/normal/handoff/chitchat，定义自主执行、用户确认与转人工边界；「保证出签/造假」等
   红队场景强制 handoff。
5. 工程排障与交付：解决 Coze LLM messages 格式导致的网关报错；完成静态 H5 与后端联调思路；
   沉淀节点说明与评测用例，便于面试演示与后续迭代。
```

**若只能留 3 条职责，保留 1、2、4（编排 + 防幻觉 + 权限）。**
