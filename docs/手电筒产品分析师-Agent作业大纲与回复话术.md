## 三、Agent 目标定义（你演示开场 20 秒用）

**Agent 名称：** PEN-X1 手电筒产品分析师（Flashlight Product Analyst Agent）

**一句话：**  
面向北美亚马逊的笔式手电新品，自动完成「竞品与评论洞察 → 机会点 → 优劣势 → 开发难点与解法 → 结构化报告」，供产品/项目决策讨论，而不是替代拍板。

**输入：**  
- 产品概念（PEN-X1、五电池兼容、$34.95）  
- 竞品资料包  
- 技术方案摘要  
- BOM / 利润假设  
- 用户画像  
- （可选）亚马逊评论 CSV / 粘贴文本  

**输出：**  
一份结构化报告（建议 Markdown/网页），固定章节见下文「最终输出模板」。

## 四、总体流程（必须让对方一眼看见「全面性」）

```text
资料摄入与校验
    ↓
模块A 市场与竞品调研结构化
    ↓
模块B 亚马逊评论痛点挖掘（好评/差评）
    ↓
模块C 新品机会点推导（对应痛点）
    ↓
模块D 优劣势（相对竞品 + 相对自身BOM/技术）
    ↓
模块E 开发难点/困难点 + 解决路径（核心加分）
    ↓
模块F 风险、假设与待验证清单
    ↓
生成结果报告（中文详版 + 英文 Executive Summary）
```

**评分对齐他的原话：**  
没有 **模块 E（难点与解法）**，前面分析视为无效——演示时把 E 讲最重。

## 五、节点设计（对标「产品分析师 Agent」）

### Node 0｜Input Gate（输入门控）

- **干什么：** 检查必填字段是否齐全（产品名、售价、电池方案、竞品列表、BOM 摘要）。  
- **缺什么就追问**（像槽位填充），不齐不下结论。  
- **输出：** `brief` 结构化 JSON（产品、价格、目标市场、约束）。

### Node 1｜Competitor Structurer（竞品结构化）

- **干什么：** 把 4 款竞品打成统一字段表。  
- **建议字段：** 定位、价格带、电池方案、亮度/续航卖点、重量尺寸、核心卖点、明显短板、适合人群。  
- **工具：** 读本地资料 / 表格解析（不必真爬）。  
- **输出：** `competitor_table`

### Node 2｜Review Insight（评论洞察）——他点名要的

- **干什么：** 对好评/差评做主题聚类与痛点排序。  
- **输入：** 评论样例或导入文件（演示用 50～200 条足够）。  
- **分析维度（全面性）：**  
  - 好点（买了为什么满意）  
  - 槽点（退货/一星高频原因）  
  - 未被满足的期望（机会）  
  - 与「多电池兼容 / 笔式 EDC / 价格带 $30–40」相关的声音  
- **输出：** `pain_points[]`（主题、频次估计、原话摘录、影响：转化/退货/口碑）

### Node 3｜Opportunity Mapper（机会点）

- **干什么：** 痛点 → 机会点 → 与 PEN-X1 卖点是否命中。  
- **规则：** 每个机会点必须追溯到至少 1 个痛点或竞品缺口。  
- **输出：** `opportunities[]`（机会描述、证据、优先级 P0/P1/P2）

### Node 4｜SWOT-lite（优势劣势）

- **干什么：** 相对竞品 + 相对自身成本/技术做优劣势（不必古典 SWOT 形式主义）。  
- **必含：**  
  - 优势：五电池兼容、$34.95 定位、笔式形态等（用资料支撑）  
  - 劣势/风险：成本、复杂度、认证、退货、认知教育成本等  
- **输出：** `pros[]` / `cons[]`

### Node 5｜Difficulty & Solutions（难点与解法）★核心

按他原话：没有这一步，前面没意义。建议固定 4～6 个难点卡：

| 难点方向 | Agent 应分析的内容 | 解法输出要求 |
|----------|-------------------|--------------|
| 五电池兼容工程 | BOOST/识别/机械补偿的复杂度与失效模式 | 分阶段验证、测试矩阵、风险缓释 |
| 成本与售价 | 48.6/57.6 元成本 vs $34.95、退货率敏感性 | 成本拆解、保利润前提、降本优先级 |
| 亚马逊竞争与差异化 | 对标四竞品如何不被当成「杂牌替代」 | 主图/标题/卖点叙事、首发评价策略 |
| 认证与合规（北美） | 电池、照明、运输、平台合规（框架级即可） | checklist + 责任方（工厂/运营） |
| 用户教育 | 「五电池」是否造成选择困难 | 说明书/详情页/开箱引导方案 |
| 退货与口碑 | 利润模型中的退货率假设 | 质检点、包装、预期管理 |

每个难点输出结构：

```text
难点名称
→ 为什么难（技术/供应链/市场）
→ 若不解决的后果（成本/差评/退货）
→ 解决路径（步骤）
→ 验证方式（测什么算过）
→ 残留风险
```

### Node 6｜Assumption & Next Tests（假设与待验证）

- **干什么：** 明确「哪些是资料给定、哪些是 Agent 推断」，列下一轮要验证的实验。  
- **体现专业：** 避免把推断写成事实。

### Node 7｜Report Writer（结果生成）

- **干什么：** 汇总为可读报告；附英文 Executive Summary（欧美市场加分）。  
- **温度：** 分析节点可低温度；报告润色可略高。

### （可选）Node Human Confirm

- 对「对外宣称卖点」「成本敏感结论」走确认节点，再生成终稿——对应你已有的 confirm/handoff 思维。

## 六、国外模型怎么用（回应「要用国外 AI」）

### 推荐组合（作业可落地）

| 用途 | 建议 |
|------|------|
| 主编排 / 深度分析 | Claude（Projects/Artifacts 或 API）或 GPT-4.1/4o |
| 结构化抽取 | 强制 JSON Schema / 函数输出 |
| 评论聚类 | 先规则/标签再 LLM 归纳，或 LLM 直接主题聚类 |
| 演示 | Claude.ai Project 或自建 LangGraph + 国外模型 API |

### 系统提示词骨架（可贴进 Agent）

```text
你是北美亚马逊消费电子（手电筒/EDC）方向的产品分析师 Agent。
你的任务是基于用户提供的资料与评论数据，输出决策辅助报告。
硬性规则：
1) 只依据给定资料与导入评论；缺失就声明假设，禁止编造竞品参数与评论原话。
2) 必须覆盖：市场/竞品、评论痛点、机会点、优劣势、开发难点与解法、待验证清单。
3) 「难点与解法」是核心章节，每个难点要有验证方式与残留风险。
4) 结论用于讨论，不代替最终商业拍板；涉及认证/法律仅给框架 checklist，并建议专业确认。
5) 输出先中文详版，再给英文 Executive Summary（10条以内要点）。
```

## 八、现场投屏演示脚本（8～10 分钟）

1. **1 min** 说明：用国外模型；评的是逻辑不是可投产数据完备性。  
2. **1 min** 展示流程图（上面模块 A–F）。  
3. **2 min** 输入资料包 + 评论样例，跑 Agent。  
4. **2 min** 展示评论痛点与机会点如何追溯。  
5. **3 min** 重点讲「难点与解法」3 个卡片。  
6. **1 min** 打开完整报告 + 英文摘要；说明可接真实评论导入。
